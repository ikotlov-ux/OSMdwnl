# Журнал изменений

## 1.8.0 — 2026-10-09

- Рецепт `hydro` (версия 4): все типы водоёмов и болот.
  - `lakes_polygon` — озёра, старицы, лагуны, пруды, плёсы (`water=lake|oxbow|lagoon|pond|stream_pool`).
  - `reservoirs_polygon` — водохранилища и искусственные водоёмы (`reservoir`, `basin`, `fishpond`, `wastewater`,
    `reflecting_pool`, `salt_pool`; legacy `landuse=reservoir|basin`).
  - `rivers_polygon` дополнен `water=stream|rapids`.
  - Новый слой `water_other_polygon` — все прочие `water=*` (каналы, канавы, рвы, шлюзы, гавани).
  - Новый слой `wetlands_polygon` — болота и заболоченные земли всех типов: `natural=wetland` с любым `wetland=*`,
    устаревшие `natural=marsh|bog|fen|swamp`, заболоченные леса и луга (`wetland=*` на `landuse=forest|meadow`).
    Крупное болото, целиком содержащее тайл, тоже загружается.
  - Поля `water_type_ru` и `wetland_type_ru` — тип объекта по-русски.
- Схема рецепта: у поля появились `values_ru`, `default_ru` и `tag: "a|b"`.

## 1.7.0 — 2026-10-05

- Overpass: «лёгкий» заголовок для тайлов, линий границ и is_in (`[timeout:120][maxsize:128 МБ]`);
  полный заголовок (180 с, 512 МБ) — только для relations целиком. Ответы с прежним заголовком берутся из кэша.
- Тайл, получивший 6 отказов «перегружен» подряд при работающих других запросах, делится на 4 (`split_after_busy`).
- Параллельная загрузка тайлов и пакетов relations: 2 потока, у каждого своё зеркало (`concurrency: 2`).
- Новый backend PBF (`--backend pbf`): выгрузки Geofabrik выбираются по AOI и скачиваются в `_osm_pbf`
  папки результата, отбор выполняется сразу для всех рецептов пакета (pyosmium), страна определяется по линиям
  госграниц, недостающие relations догружаются через Overpass. После успешного завершения файлы удаляются
  (`--keep-pbf`, `pbf.keep_files`).
- Окно: «Источник» (авто / Overpass / PBF). В режиме «авто» для AOI больше 25 град² показывается оценка
  Overpass и PBF (тайлы, время, список и объём выгрузок) и предлагается выбор.
- Зависимость: `osmium` (pyosmium ≥ 4) — только для PBF.

## 1.6.0 — 2026-10-05

- Новый рецепт `roads` — «Автомобильные дороги»: основные дороги motorway–tertiary со съездами
  (номер, покрытие, полосы, скорость, мосты и тоннели). По галочкам: местные дороги и улицы,
  служебные проезды, грунтовые и полевые дороги (track); выключенные слои не запрашиваются.
- Окно: список рецептов прокручивается (колесо мыши или полоса прокрутки), журнал не сжимается.

## 1.5.0 — 2026-10-05

- Новый рецепт `railways` — «Железные дороги»: пути `railway=rail|narrow_gauge` (назначение,
  колея, электрификация, напряжение, число путей, скорость, мосты и тоннели) и станции
  с остановочными пунктами (коды ЕСР и «Экспресс»). По галочкам: служебные пути,
  городской рельсовый транспорт, недействующие и строящиеся линии; выключенные слои
  не запрашиваются.

## 1.4.0 — 2026-10-03

- `hydro`: новый слой `seas_polygon` — моря (`place=sea|ocean`, way и multipolygon). Каспийское
  море (`natural=water + water=lake + place=sea`) теперь попадает в моря, а не в озёра.
  Приоритет площадных классов: моря → реки → водохранилища → озёра → без water=*.
- `hydro`: в `lakes_polygon` добавлены старицы (`water=oxbow`) и лагуны (`water=lagoon`).
- `hydro`: море, озеро или водохранилище, целиком накрывающее тайл, тоже попадает в выборку.
- Новый рецепт `settlements` — «Населённые пункты»: точки (узлы `place=*`) и контуры
  (city, town, village, hamlet, isolated_dwelling), поля `population`, `capital`,
  `official_status` и др. Точки и контуры связаны полями `polygon_uid` / `point_uid`; для
  контуров без узла по умолчанию добавляется внутренняя точка (`point_source = polygon`).
- Схема рецепта: раздел `links` (связь точечного и площадного слоёв).

## 1.3.0 — 2026-10-03

- Рецепты без привязки к России и Казахстану в названиях: `admin_districts` («Административные
  районы»), `hydro` («Гидрография»), `state_borders` («Государственные границы»). Прежние ID
  и режим `ru_kz_shared_only` работают как синонимы.
- Новый рецепт `admin_regions` — «Административные области (края, республики)»: admin_level=4,
  поле `iso3166_2`, тайлы до 16 град².
- Поле «Страны» в окне и параметр `--countries` (ISO 3166-1 alpha-2) задают страны для всех
  рецептов; по умолчанию RU, KZ. Для стран без своего профиля используется раздел `default`
  в `country_profiles`.
- `state_borders`, режим `shared_only`: участки между любыми двумя выбранными странами
  (а не только RU-KZ).
- Районы и области, целиком содержащие тайл (без своей границы внутри него), теперь тоже
  попадают в выборку (`include_enclosing`); раньше маленький AOI внутри одной единицы мог
  дать пустой слой.
- Изменились ID и тексты рецептов, поэтому кэш прежних запусков для них не используется.

## 1.2.3 — 2026-10-02

- Пауза для медленного зеркала растёт с каждым неудачным разом подряд: 2, 4, 8… мин (не больше 30)
  и сбрасывается после успешного ответа. Зеркало, которое отвечает «перегружен» только через
  2–4 минуты, перестаёт съедать время.
- При переключении на другой сервер пауза перед запросом — до 5 с, а не до 70 с; при повторе
  на том же сервере пауза ограничена 60 с.

## 1.2.2 — 2026-10-02

- Исправлено: тайм-аут чтения ответа (requests выдаёт его как ConnectionError) считался отсутствием
  соединения, и основной сервер overpass-api.de отключался на 15 мин. Теперь медленное зеркало
  отключается на 2 мин (`slow_endpoint_cooldown_seconds`), на 15 мин — только при реальном отсутствии соединения.
- Короткие страницы 502/503/504 от прокси (0.2 КБ за 0.3 с) считаются перегрузкой и не тратят попытки.
- Пакет relations, который не удалось загрузить, делится пополам, а не обрывает весь рецепт.
  Размер пакета 100 (было 40); пакеты по 40 из кэша прежних версий используются повторно.
- retries 8, busy_retries 20.

## 1.2.1 — 2026-10-01

- Исправлено: рецепты с `$profile` (admin_districts_ru_kz) падали с E_RECIPE в ускоренном режиме.
  Теперь выборка по bbox делается отдельно для каждой страны с её профилем.
- При сбое `is_in` медленный фильтр по areas включается только для затронутых тайлов, а не для всех;
  пакеты `is_in` уменьшены до 25 точек.
- Недоступное зеркало (нет соединения) отключается на 15 мин, зависающее (read timeout или «перегружен»
  через минуты) — на 5 мин (`overpass.endpoint_cooldown_seconds`).
- На быстрый ответ «перегружен» программа ждёт и повторяет запрос на том же сервере; на зеркало
  переключается только с 3-го раза.

## 1.2.0 — 2026-10-01

- Ускорение примерно в 5–10 раз для рецептов с `country_scope: area`. Вместо фильтра `(area.c_XX)`
  используются линии госграниц в AOI и `is_in` по частям тайлов (`overpass.smart_country_filter`).
- Участки объектов, проходящие ровно по линии госграницы, больше не теряются (`country_code = KZ;RU`).
- «Server too busy»/429 обрабатываются отдельными повторами с нарастающей паузой и сменой зеркала,
  тайл при этом не делится (`overpass.busy_retries`).
- Тайлы, загруженные прежней версией, берутся из кэша.

## 1.0.0 — 2026-10-01

Первая версия (MVP по ТЗ):

- CLI и интерактивный режим; коды возврата 0/2–7;
- AOI из GPKG/SHP/GeoJSON/KML/GDB/FGB и других форматов GDAL либо `--bbox`; режимы `envelope`/`geometry`; антимеридиан;
- backend Overpass API: зеркала, повторы, backoff с jitter, `/api/status`, кэш `.json.gz`, тайлинг и рекурсивное дробление, двухэтапная загрузка relations, привязка к странам через `area`, уточнение через `is_in`;
- парсер Overpass JSON и сборка multipolygon/boundary relations (even-odd, резервный polygonize);
- декларативные YAML-рецепты (Pydantic) — `admin_districts_ru_kz`, `hydro_ru_kz`, `state_borders_ru_kz`;
- запись GeoPackage с RTree-индексом, метаданными, статистикой и предупреждениями; атомарная замена после QC;
- 39 автотестов (фикстуры реальных ответов Overpass и синтетика);
- PBF и PostGIS — зарезервированный интерфейс (вторая очередь).

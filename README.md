# OSMdwnl 1.8.0

Загрузка тематических слоёв OpenStreetMap для области интереса (AOI) в GeoPackage.
**Один логический запрос (рецепт) — один файл `.gpkg`**; внутри может быть несколько слоёв
и служебные таблицы с метаданными, статистикой и предупреждениями. Результат открывается
в QGIS, ArcGIS Pro и ArcMap 10.8. `arcpy` не требуется.

## Установка (Windows, Conda)

```bat
conda env create -f environment.yml
conda activate osmdwnl
copy config.example.yml config.yml        :: впишите свой контакт в overpass.user_agent
python OSMdwnl.py --list-recipes
python -m pytest -q tests                 :: 62 теста, сеть не нужна
```

## Окно выбора файлов (GUI)

Запуск **без параметров** открывает окно:

```bat
python OSMdwnl.py          :: из консоли
```
```python
%run OSMdwnl.py            # из Jupyter / JupyterLab
```

1. «Добавить файлы...» открывает проводник; можно выделить сразу несколько файлов AOI (Ctrl/Shift). Если в GPKG или GDB несколько слоёв, появится список, где можно выбрать один или несколько слоёв. Вместо файлов можно задать bbox.
2. Отметьте один или несколько рецептов и при необходимости их параметры: береговую линию, режим границы, морские участки и т. д.
3. Выберите папку результата («Обзор...»), режим обрезки, CRS и перезапись.
4. «Показать план» выводит запросы без загрузки, «Запустить» выполняет загрузку.

Каждая пара «AOI × рецепт» даёт отдельный GeoPackage. Журнал выводится в окно, итог показывается списком файлов.
Последние настройки (папки, рецепты) запоминаются. Для принудительного запуска окна используйте `--gui`, для текстового диалога в консоли — `--console`.
В Jupyter скрипт больше не вызывает `sys.exit`, поэтому сообщения «An exception has occurred» не будет.

## Примеры

```bat
:: Гидрография по экстенту AOI из GeoPackage
python OSMdwnl.py --aoi "D:\GIS\aoi.gpkg" --aoi-layer aoi --recipe hydro --output "D:\GIS\OSM"

:: Районы по bbox (west south east north), обрезать по AOI
python OSMdwnl.py --bbox 54 50.5 56 51.5 --recipe admin_districts --clip --output "D:\GIS\OSM"

:: Только общая граница RU–KZ, включая морские участки
python OSMdwnl.py --bbox 54.6 50.6 55.4 51.4 --recipe state_borders ^
       --param mode=shared_only --param include_maritime=true --output "D:\GIS\OSM"

:: Точная обрезка по полигону AOI, береговая линия, результат в EPSG:3857
python OSMdwnl.py --aoi examples\махачкала_aoi.geojson --aoi-mode geometry --recipe hydro ^
       --enable-layer coastline_line --output-crs EPSG:3857 --output "D:\GIS\OSM"

:: План и полный текст запросов без обращения к сети
python OSMdwnl.py --bbox 50 49 52 51 --recipe hydro --dry-run
```

Текстовый интерактивный режим в консоли: `python OSMdwnl.py --console`.

Имя файла по умолчанию: `{recipe}__{aoi}__{YYYYMMDD}.gpkg`. Можно передать `--output путь\файл.gpkg`.

## Рецепты

| ID | Слои | Параметры (`--param`) |
|---|---|---|
| `admin_regions` | `admin_regions` | области, края, республики; уровни в `country_profiles` YAML (`admin_level=4`, раздел `default` для прочих стран); сохраняются целиком, `--clip` обрезает |
| `admin_districts` | `admin_districts` | уровни в `country_profiles` YAML (`admin_level=6`, раздел `default` для прочих стран); районы сохраняются целиком, `--clip` обрезает |
| `roads` | `roads_main_line`; опционально `roads_local_line`, `roads_service_line`, `roads_track_line` | `local_roads=true`, `service_roads=true`, `tracks=true` |
| `railways` | `railways_line`, `railway_stations_point`; опционально `railway_service_line`, `urban_rail_line`, `railway_inactive_line` | `stations=false`, `service_tracks=true`, `urban_rail=true`, `inactive=true` |
| `settlements` | `settlements_point`, `settlements_polygon` | `points_from_polygons=false` — не добавлять точки для контуров без узла `place=*` |
| `hydro` | `rivers_line`, `seas_polygon`, `rivers_polygon`, `reservoirs_polygon`, `lakes_polygon`, `water_other_polygon`, `wetlands_polygon`, `seas_point`; опционально `coastline_line`, `water_unclassified` | `wetlands=false`, `water_other=false`, `coastline=true`, `water_unclassified=true` |
| `state_borders` | `state_border_line`; опционально `country_outlines` | `mode=all_target_borders` или `shared_only`, `include_maritime=true`, `country_outlines=true` |

Страны рецептов по умолчанию — RU, KZ. Их меняют полем «Страны» в окне или параметром
`--countries RU,KZ,BY` (коды ISO 3166-1 alpha-2). Для стран без своего профиля в
`country_profiles` берётся раздел `default`. Прежние ID (`admin_districts_ru_kz`, `hydro_ru_kz`,
`state_borders_ru_kz`) и режим `ru_kz_shared_only` продолжают работать.

Схема YAML описана в [docs/recipe_schema.md](docs/recipe_schema.md), поля слоёв — в [docs/fields.md](docs/fields.md).
Новые рецепты добавляются файлом YAML в `recipes/` или в папку из `recipe_dirs` в `config.yml`,
без изменения Python-кода. YAML читается через `safe_load`, и произвольный код в нём не выполняется.
Сырой Overpass QL допускается только в рецептах `type: raw_overpass` с флагом `--allow-raw-query`.

## Чем bbox отличается от точной геометрии AOI

- `--aoi-mode envelope` (по умолчанию): запрос и обрезка выполняются по прямоугольному экстенту всех объектов AOI.
- `--aoi-mode geometry`: запрос идёт по экстенту, а итоговая обрезка выполняется по точному полигону. Тайлы вне полигона не запрашиваются.
- `--no-clip`: сохранять объекты OSM целиком, если они пересекают AOI.

AOI в любой CRS перепроецируется в EPSG:4326. Если CRS не задана (например, у SHP без .prj), нужно указать `--aoi-crs`.
AOI, пересекающий антимеридиан, автоматически делится на два bbox.

## Overpass, PBF и PostGIS

В версии 1.0 реализован **Overpass API**. Он подходит для малых и средних AOI. Работа с Overpass устроена так:

- bbox больше `tiling.max_bbox_area_deg2` (по умолчанию 1 град², у районов и границ 4 град²) делится на тайлы;
- при timeout/out of memory тайл рекурсивно делится на 4 (до `max_split_depth`);
- relations (районы, мультиполигоны озёр) загружаются вторым этапом пакетами по ID со всеми членами, поэтому на стыке тайлов геометрия не обрывается;
- одновременно выполняется только один запрос; при HTTP 429/502/503/504 используется экспоненциальная пауза с jitter, затем происходит переключение на другое зеркало; `/api/status` проверяется перед запросом;
- ответы кэшируются в `%LOCALAPPDATA%\OSMdwnl\cache` (.json.gz, TTL 30 дней). Повторный или прерванный запуск берёт готовые тайлы из кэша.

Для AOI больше 25 град² рекомендуется PBF, для Overpass больше 400 град² запуск требует `--force`.

### PBF (с версии 1.7.0)

`--backend pbf` или «Источник: PBF Geofabrik» в окне. Нужен пакет `osmium` (pyosmium ≥ 4):
`pip install osmium` или `conda install -c conda-forge pyosmium`.

1. По индексу Geofabrik выбираются самые мелкие выгрузки, покрывающие AOI (федеральные округа,
   страны). Они скачиваются в подпапку `_osm_pbf` папки результата, с докачкой при обрыве.
2. Каждая выгрузка читается двумя проходами (relations; узлы и линии с координатами). Объекты отбираются
   сразу для всех рецептов пакета, следующие задания берут готовый отбор.
3. Страна объектов определяется по линиям госграниц, для этого нужно несколько лёгких запросов Overpass.
   Если Overpass недоступен, страна берётся по выгрузке Geofabrik (у самой границы это приблизительно).
4. Relations, часть членов которых лежит вне скачанных выгрузок, догружаются целиком через Overpass.
5. После успешного завершения всех заданий скачанные файлы и промежуточные данные удаляются
   (`--keep-pbf` или `pbf.keep_files: true` — оставить). Если задание прервано или завершилось
   ошибкой, выгрузки остаются для повторного запуска.

В режиме «авто» окно оценивает площадь AOI. Если она больше `planner.recommend_pbf_area_deg2`,
окно показывает число тайлов Overpass и ориентировочное время, список и объём выгрузок PBF
и предлагает выбрать источник. Данные Geofabrik обновляются ежедневно, дата выгрузки записывается
в `source_data_timestamp`. Backend **PostGIS** (osm2pgsql) остаётся в следующей очереди.

## Скорость загрузки

Самая медленная часть Overpass-запроса — фильтр «внутри страны» `(area.c_RU)`: сервер каждый раз
обрабатывает полигон всей России, это около 50 с на тайл независимо от его размера. Начиная с 1.2.0
этот фильтр не используется:

1. Один лёгкий запрос получает линии госграниц стран рецепта в пределах AOI (1–3 с).
2. Тайл без линий границы целиком лежит в одной стране. Её определяет один пакетный `is_in`
   по центрам тайлов, а сам тайл запрашивается только по bbox (4–10 с вместо 50–60 с).
3. Тайл с границей тоже запрашивается по bbox. Линии границы делят его на части, страна каждой части
   определяется через `is_in`, а страна объекта — по частям, которые он пересекает.

Проверка на тайлах по границе RU–KZ (Астраханская обл., р. Урал/Илек): классы и состав объектов
совпадают с прежним режимом. Отличие одно: участки рек, проходящие ровно по линии границы
(Хобда, Илек и др.), прежний фильтр по areas терял, теперь они сохраняются с `country_code = KZ;RU`.

Ещё изменилось:
- Ответ «server too busy»/429 больше не приводит к делению тайла. Программа ждёт 10, 20, 30… с,
  пробует зеркало и не тратит обычные попытки (`busy_retries`).
- Тайлы, уже загруженные прежней версией, берутся из кэша, поэтому прерванную загрузку можно продолжить.
- Вернуть прежний режим: `smart_country_filter: false` в config.yml.

С версии 1.7.0:
- Тайлы, линии границ и `is_in` заявляют серверу 120 с и 128 МБ вместо 180 с и 512 МБ.
  Перегруженный Overpass охотнее принимает такие запросы. Полный заголовок остаётся только для
  загрузки relations целиком. Ответы, полученные прежними версиями, по-прежнему берутся из кэша.
- Тайл, которому 6 раз подряд ответили «перегружен», в то время как другие запросы проходят,
  делится на 4 части (`split_after_busy`).
- Запросы идут в 2 потока, у каждого своё зеркало (`concurrency: 2`, максимум 3). Если в вашем
  config.yml осталось `concurrency: 1`, замените значение на 2.

Для территорий от нескольких десятков градусов² быстрее всего PBF.

## Почему в одном GPKG несколько слоёв

Рецепт описывает одну тематическую задачу. Например, гидрография даёт линии рек, площадные русла,
озёра, водохранилища и подписи морей. Это разные типы геометрии, поэтому они записываются отдельными слоями
одного контейнера. Каждый водный полигон попадает только в один класс. Приоритет такой: река → водохранилище → озеро;
новый тег `water=*` важнее legacy-тегов `waterway=riverbank` и `landuse=reservoir`.

## Служебные таблицы внутри GPKG

- `osm_download_metadata`: run_id, рецепт, его версия, SHA-256 и параметры, время, AOI (источник, слой, CRS, WKT), bbox в порядках WSEN и Overpass SWNE, backend/зеркало, хэш и полный текст всех физических запросов, дата среза OSM (`timestamp_osm_base`), режим обрезки, CRS результата, версии ПО, лицензия, атрибуция, статус;
- `osm_layer_statistics`: downloaded / duplicates / filtered / invalid / clipped_out / written по слоям;
- `osm_processing_warnings`: незамкнутые relations, ways района без relation, конфликты тегов и т. п.

Перед заменой итогового файла выполняется контроль качества: открываемость в GDAL, наличие слоёв и типов геометрии, CRS,
RTree-индекс, валидность и непустота геометрий, уникальность `osm_uid + part_no`, пересечение с AOI и согласованность
числа объектов. Запись идёт во временный `*.tmp.gpkg`, после проверки он атомарно заменяет целевой файл. Если файл
открыт в ArcGIS/QGIS, существующий результат не повреждается.

Коды возврата: `0` — успех; `2` — аргументы/AOI; `3` — рецепт; `4` — сеть/API; `5` — парсинг/геометрия;
`6` — запись/блокировка GPKG; `7` — контроль качества. Подробный журнал пишется в `%LOCALAPPDATA%\OSMdwnl\logs`.

## Ограничения данных OSM

- Полнота и актуальность OSM неоднородны; пустой слой не доказывает отсутствие объектов на местности.
- `name_ru` — строго тег `name:ru`. `name_display` использует `name` как запасной вариант, источник указан в `name_source`. Машинный перевод не применяется.
- **Государственная граница по OSM не является официальным юридическим источником.** Предупреждение записывается в метаданные.
- Моря в OSM обычно представлены точкой `place=sea`, а не полигоном. Поэтому в версии 1.0 есть `seas_point` и опционально `coastline_line`. Каспий в OSM размечен как `natural=water` + `water=lake` и попадает в `lakes_polygon`.
- Уровни `admin_level` различаются по странам и хранятся в профиле рецепта.
